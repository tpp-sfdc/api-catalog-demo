# API Catalog CLI Demo — GitHub → Anypoint Exchange

A live demo of the **Anypoint API Catalog CLI**: the Git repository is the
source of truth for API specs, and one command detects new/changed APIs and
publishes them to **Anypoint Exchange** — the "shift-left, CI-friendly"
cataloging story.

## The flow

```
GitHub repo of specs  ──①──▶  git pull        (call the external API repository)
                      ──②──▶  update-descriptor (auto-detect new APIs / version changes)
                      ──③──▶  publish-asset --dry-run  (preview — publishes nothing)
                      ──④──▶  publish-asset    (upload new + changed assets to Exchange)
```

All four steps are wrapped in [`sync-to-exchange.sh`](./sync-to-exchange.sh).

## Repo layout

```
api-catalog-demo/
├── apis/
│   ├── orders-api/orders-api.yaml       # OpenAPI 3.0
│   ├── customers-api/customers-api.yaml
│   └── shipping-api/shipping-api.yaml
├── catalog.yaml            # descriptor — generated by the CLI, not hand-written

├── .env.example            # copy to .env, add Connected App creds
└── .gitignore              # ignores .env and config.json
```

## Prerequisites (already in place on this machine)

- `api-catalog` CLI — v1.1.19 (`api-catalog --version`)
- Node.js 24 / npm 11
- An Anypoint Platform account with access to a business group

> Install elsewhere with: `npm install -g api-catalog-cli`

## One-time setup: Connected App

The CLI authenticates to Exchange with a **Connected App** (client id + secret).

1. Anypoint Platform → **Access Management → Connected Apps → Create app**.
2. Type: **App acts on its own behalf (client credentials)**.
3. Add scopes (per MuleSoft docs):
   - **API Catalog Contributor** — required to publish assets.
   - **View Environment** — on the environment you publish into (needed for
     Connected App auth).
4. Save, then copy the **Client ID** and **Client Secret**.
5. Configure this repo:
   ```bash
   cp .env.example .env
   # edit .env: set ANYPOINT_ORG, ANYPOINT_CLIENT_ID, ANYPOINT_CLIENT_SECRET
   ```

> **Heads-up on `ANYPOINT_ORG`:** MuleSoft's docs describe `--organization` as
> the organization **ID** (a UUID — find it in Access Management, it's in the
> URL). The CLI's own `--help` labels it "Organization Name." Use the **ID** to
> match the docs; if auth fails, try the business-group name. Set
> `ANYPOINT_ENV` too if you're not publishing to the default environment.

> `.env` is git-ignored, so credentials never get committed.

## Run the demo

```bash
# Preview only — validates the descriptor + auth, publishes nothing
./sync-to-exchange.sh --preview

# Full run — detects changes and publishes to Exchange
./sync-to-exchange.sh
```

Then open **Anypoint Exchange** to show the assets appear.

## The two "wow" moments

**A brand-new API shows up in Exchange**
```bash
mkdir -p apis/returns-api
cp apis/orders-api/orders-api.yaml apis/returns-api/returns-api.yaml
# tweak title -> "Returns API" in that file
./sync-to-exchange.sh
```
`update-descriptor` prints *"The following APIs were added: …"* and only the new
asset is published.

**A new version of an existing API**
```bash
# bump info.version in apis/orders-api/orders-api.yaml: 1.0.0 -> 1.1.0
./sync-to-exchange.sh
```
The CLI is **content-aware**: unchanged specs are skipped, and a version bump
publishes a *new* Exchange version alongside the old one. How the new version
number is computed is set per project in the descriptor's `versionStrategy`
field (`patchIncrease` (default), `minorIncrease`, `majorIncrease`, `Snapshot`,
`Fixed`). Use `--force-publish` to force a new version regardless of content.

## Talking points for the customer

- **APIs live in source control** — Git is the single source of truth; Exchange
  stays in sync automatically.
- **No custom diffing code** — change detection is native to the CLI.
- **CI/CD-native** — the CLI is agnostic of the pipeline; the same command runs
  in GitHub Actions, Jenkins, etc. `--dry-run` gates PRs; publish runs on merge.
- **Governance** — publishing is gated by Connected App scopes and business
  group, so only authorized assets reach the catalog.
